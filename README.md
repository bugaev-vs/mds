# mds
## Мультимодальная диспетчерская система управления городским беспилотным транспортом (школьный проект)
## Что это

Программная система, которая **согласовывает маршруты автономного городского транспорта** четырёх типов: тротуарные роверы, беспилотные автомобили, воздушные дроны и водные суда. Система **не управляет** транспортом — она работает как «ГИБДД для дронов»: принимает заявки, проверяет их на конфликты и выдаёт разрешения.

## Зачем нужна

В городе одновременно движутся десятки автономных транспортных средств от разных служб доставки. Без единого координатора они будут сталкиваться, блокировать друг друга и нарушать запретные зоны. Диспетчер решает три задачи:

1. **Безопасность** — не допустить столкновений и полётов над запретными зонами.
2. **Эффективность** — распределить маршруты так, чтобы коридоры не перегружались.
3. **Учёт реальности** — ремонты, закрытые участки, мели, разводные мосты.

## Как работает: полный цикл

```
Магазин → Заявка → Проверка → Согласование → Полёт → Телеметрия → Актуализация
```

1. **Магазин подаёт заявку** — начальная и конечная точка, предлагаемый маршрут, время вылета, тип транспорта.
2. **Диспетчер проверяет** — пересечение с препятствиями, загруженность коридора, конфликты по времени.
3. **Решение** — согласовано / согласовано с изменениями / отклонено (с рекомендациями).
4. **Согласованный маршрут** вносится в **карту занятости** — он влияет на все последующие заявки.
5. **Клиент отправляет телеметрию** каждые 2–5 секунд: позиция, прогресс, ETA, статус, алерты.
6. **Диспетчер актуализирует** — сравнивает факт с планом, продлевает окна, запрашивает перестройку.

## Ключевые компоненты

| Компонент | Назначение |
|---|---|
| **CityMap** | Препятствия: лестницы, перекопы, запретные зоны, мели, мосты |
| **Dispatcher** | Ядро: приём заявок, проверка, согласование |
| **OccupancyMap** | Карта занятости: какие маршруты где и когда активны |
| **Detector** | Детект отклонений: время, пространство, прогресс |
| **Validator** | Проверка контракта телеметрии от клиентов |
| **Visualizer** | Карта города, временные окна, метрики |

## Четыре среды — четыре правила

| Тип | Среда | Особые препятствия |
|---|---|---|
| **Ровер** | Тротуары | Лестницы, узкие проходы, скопления людей |
| **Автомобиль** | Дороги | Перекопы, светофоры, закрытые полосы |
| **Дрон** | Воздух | Запретные зоны, эшелоны высот |
| **Катер** | Вода | Шлюзы, разводные мосты, мели, осадка |

## Контракт телеметрии

Клиент сам собирает данные со своих бортов и отправляет пакет в едином формате (JSON):

```json
{
  "client_id": "pizza_shop_01",
  "batch_id": "batch-001",
  "vehicles": [{
    "vehicle_id": "rover_007",
    "route_id": "R-001",
    "position": {"x": 12.5, "y": 34.2},
    "status": "moving",
    "progress": 0.35,
    "eta": "2025-06-01T14:12:00Z",
    "alerts": []
  }]
}
```

Система валидирует пакет по схеме, проверяет принадлежность маршрута клиенту и свежесть данных.

## Что важно понимать

- **Диспетчер — арбитр, а не пилот.** Он не строит маршрут за клиента, а проверяет предложенный.
- **Каждое согласование влияет на следующие.** Это ключевая идея: карта занятости накапливает данные.
- **Обратная связь замыкает контур.** Без телеметрии система работает вслепую.
- **Архитектура масштабируема.** Новый тип транспорта = новый модуль проверки, ядро не меняется.

## Технологии

Python 3.10+, Flask, Pydantic, Shapely, networkx, matplotlib, WebSocket.

## С чего начать новому участнику

1. Прочитайте `models.py` — базовые структуры данных.
2. Запустите `main.py` — увидите полный цикл на демо-сценарии.
3. Изучите `dispatcher.py` — ядро логики.
4. Посмотрите три графика: карта города, временные окна, метрики.
